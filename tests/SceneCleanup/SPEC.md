# Scene Cleanup 모듈 동작 명세 (클린룸)

작성: Claude. 이 문서는 동작만 설명한다. 다른 모드의 코드, 식별자, 구조, 이름 목록을 담지 않는다.
구현자는 이 문서, 게임 어셈블리, 아래 `scene-names` 자료만 근거로 처음부터 새로 쓴다.

## 목적
Escape from Tarkov(SPT 4.1, Unity 2022.3, BepInEx 5) 레이드에서, 게임 진행과 무관한 작은 장식 물체를 그리지 않아 프레임을 올린다.
Tushonka Cleaner의 `그래픽` 기능이다. 사용자에게 보이는 이름은 한국어 `그래픽`, 영어 `Graphics`다.

## 단계
사용자는 네 단계 중 하나를 고른다. 단계 값은 코드에서 Off, LightTouch, Balanced, Max로 부른다.

| 단계 | 한국어 이름 | 동작 |
|---|---|---|
| Off | 끔 | 아무것도 바꾸지 않는다 |
| LightTouch | 간단하게만 가림 | 대상 물체를 멀리 있을 때만 숨긴다. 가까이 가면 보인다 |
| Balanced | 균형 | 대상 물체를 거리와 무관하게 숨긴다. 가벼운 그래픽 조정을 더한다 |
| Max | 최대 | Balanced에 강한 그래픽 조정을 더한다 |

## 대상 물체 고르기
- 대상 분류: 바닥 쓰레기, 잔해 더미, 맵에 고정된 탄피, 먹을 수 없는 장식 음식, 물웅덩이, 깨진 유리 조각, 벽과 바닥의 얼룩·낙서. 각 분류를 사용자가 고급 설정에서 켜고 끌 수 있다.
- 분류 규칙은 데이터 파일 `data/scene-rules.json`에 둔다. 구현자가 `scene-names/names-*.csv`를 직접 분석해 새로 만든다. 이 CSV 열은 정규화한 물체 이름, 렌더러 종류, 개수, 평균 크기(m), 콜라이더 비율, 정적 비율이다.
- 규칙은 이름 패턴과 크기 상한을 함께 쓴다. 맵마다 잘못 걸리는 이름이 없는지 CSV로 검사하고, 그 결과를 RESULT.md에 표로 적는다.
- 사용자 제외 파일 `tushonka-exclude.txt`를 지원한다. 한 줄에 이름 패턴 하나다.

## 절대 숨기면 안 되는 것
게임 진행을 바꾸면 안 된다. 아래는 어떤 규칙에 걸려도 숨기지 않는다.
- 플레이어, 봇, 시체, 무기, 장비.
- 주울 수 있는 아이템, 상자, 문, 스위치, 탈출구, 퀘스트 물체 등 상호작용 물체와 그 자식.
- 봇이나 플레이어의 이동과 총알을 막는 콜라이더를 가진 물체. 렌더러만 끄고 콜라이더는 남기는 방식으로도 숨기지 않는다. 눈에 안 보이는 벽이 생기기 때문이다. 봇의 시야 계산에 영향을 주는 물체도 같다.
- 게임이 재사용하는 이펙트 풀, 씬 전환에도 살아 있는 물체.

## 실행 규칙
- 레이드 시작 뒤 맵이 자리 잡을 시간을 기다린 다음 검사한다. 시간은 설정값이다.
- 물체 검사와 적용은 프레임당 시간 예산(기본 2ms, 설정값) 안에서 나눠서 한다. 레이드 시작을 포함해 이 모듈 때문에 16ms 넘는 프레임이 나오면 안 된다.
- 프레임마다 메모리를 할당하지 않는다. LINQ, 문자열 조합, 임시 리스트 생성을 반복 경로에 쓰지 않는다.
- 단계를 바꾸면 레이드 중에도 예산 안에서 다시 적용한다. Off로 돌리면 원래 상태로 정확히 복원한다.
- 레이드가 끝나면 모듈이 잡고 있는 씬 물체 참조를 모두 비운다. 정적 필드에 지난 레이드 물체가 남으면 안 된다. 이 항목은 누수 탐지 시험으로 검사한다.

## 게임 사실 (측정으로 확인한 것)
- 맵의 얼룩·낙서(데칼)를 레이드 중 비활성화하면 게임이 버퍼를 다시 만들어 분당 수백 MB 할당과 프레임당 수 ms 비용이 생겼다. 데칼은 맵을 불러올 때 등록을 막는 방식으로 제외해야 한다. 그래서 데칼 설정 변경은 다음 레이드부터 적용되며, 화면에 그렇게 안내한다.
- 게임 어셈블리를 직접 읽어 해당 지점을 찾는다.
- 먼 거리 숨김은 조준 배율을 고려한다. 6배율처럼 시야각이 좁을 때 숨김 거리를 어떻게 처리할지 구현자가 정하고 이유를 RESULT.md에 쓴다. 조준 순간 많은 물체가 한꺼번에 켜져 끊기면 안 된다.
- 다른 모드가 주 카메라 시야각을 바꿀 수 있다. 시야각은 매번 현재 값을 읽는다.

## 그래픽 조정
Balanced와 Max에서 쓰는 조정이다. 각 항목은 고급 설정에서 따로 켜고 끌 수 있고, 끄면 원래 값으로 돌아간다. 값은 구현자가 게임 품질 설정을 읽어 정한다.
- 파티클 부담 줄이기, 부드러운 파티클·식생 끄기, 실시간 반사 줄이기, 그림자 단계 줄이기, 픽셀 조명 수 줄이기, 멀리 있는 모델 단순화 정도 조정.
- 바닥에 쌓이는 탄피 수와 총알 자국 수 상한.
- 다른 사람의 총구 화염이 만드는 그림자 끄기. 내 총의 불빛은 유지한다.

## 코드 구성
- 위치: 이 폴더의 `src/SceneCleanup/`. 네임스페이스 `Tushonka.Cleaner.SceneCleanup`. 라이선스 GPL-3.0 프로젝트에 들어간다.
- 진입점은 이것뿐이다.
  - `SceneCleanupModule.Init(ConfigFile config, ManualLogSource log, string dataDir)`
  - `SceneCleanupModule.Tick()`: 플러그인 Update에서 프레임마다 호출한다.
  - `SceneCleanupModule.SetLevel(SceneCleanupLevel level)`
  - `SceneCleanupModule.GetStatus()`: 단계, 검사 후보 수, 분류별 숨김 수, 마지막 적용 시간(ms)을 값 형식으로 준다.
  - `SceneCleanupModule.Shutdown()`
- 설정은 받은 `ConfigFile`에 `Graphics`로 시작하는 섹션을 만들어 저장한다. 설명 문구는 한국어와 영어를 둘 다 준비한다.
- 빌드 검증용 `SceneCleanup.csproj`를 둔다. 대상 net471. 참조는 `E:\SPT 4.1\EscapeFromTarkov_Data\Managed`와 `E:\SPT 4.1\BepInEx\core`다.
- 게임 없이 돌릴 수 있는 규칙 판정 시험을 넣는다.
